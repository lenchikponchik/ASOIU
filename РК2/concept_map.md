## Ядро: Архитектура программных систем

```
АРХИТЕКТУРА ПРОГРАММНЫХ СИСТЕМ
│
├─[опирается на]──► ПРИНЦИПЫ ПРОЕКТИРОВАНИЯ
│   │
│   ├─[включает]──► SOLID
│   │   ├─ SRP  "один класс — одна причина меняться"
│   │   ├─ OCP  "открыт для расширения, закрыт для изменения"
│   │   ├─ LSP  "подтипы полностью заменяют базовый тип"
│   │   ├─ ISP  "клиент зависит только от нужных методов"
│   │   └─ DIP  "зависимость от абстракций, не реализаций"
│   │
│   └─[включает]──► ДОПОЛНИТЕЛЬНЫЕ ПРИНЦИПЫ
│       ├─ DRY   "не повторяй себя"
│       ├─ KISS  "простота лучше сложности"
│       └─ YAGNI "не делай то, что не нужно сейчас"
│
├─[реализуется через]──► ВНЕДРЕНИЕ ЗАВИСИМОСТЕЙ (DI)
│   │
│   ├─[способы]──► через конструктор  ← [предпочтительный]
│   ├─[способы]──► через свойство     ← [необязательная зависимость]
│   ├─[способы]──► через параметр метода
│   │
│   ├─[точка сборки]──► Pure DI   ← [явное ручное связывание]
│   ├─[точка сборки]──► DI-контейнер
│   │   └─ Microsoft.Extensions.DependencyInjection
│   │       ├─ Singleton   "один экземпляр на всё время"
│   │       ├─ Transient   "новый объект при каждом запросе"
│   │       └─ Scoped      "один объект на скоуп"
│   │
│   └─[антипаттерны]──► Control Freak
│                    ──► Bastard Injection
│                    ──► Service Locator
│                    ──► Ambient Context
│
├─[реализуется через]──► ПАТТЕРНЫ ПРОЕКТИРОВАНИЯ
│   │
│   └─[поведенческие]──► Стратегия (Strategy)
│       ├─ Интерфейс (IFineRule)
│       ├─ Конкретные стратегии (Regular / Student / Senior / Staff / Family)
│       └─ Контекст (FineCalculator) ← [делегирует стратегии]
│
├─[проверяется через]──► ТЕСТИРОВАНИЕ
│   │
│   ├─[фреймворк]──► xUnit
│   │   ├─ [Fact]    "одиночный тест"
│   │   └─ [Theory] + [InlineData]  "параметризованный тест"
│   │
│   ├─[тестовые дублёры]──► Stub    "заглушка с заданными данными"
│   │                    ──► Mock    "проверяет вызовы"  (Moq)
│   │                    ──► Dummy   "заполнитель, не используется"
│   │
│   ├─[подход]──► AAA: Arrange / Act / Assert
│   ├─[подход]──► TDD  "сначала тест, потом код"
│   │
│   └─[тестируемость обеспечивается]──► DI + абстракции
│                                    ──► IClock   "абстракция времени"
│
├─[улучшается через]──► РЕФАКТОРИНГ
│   ├─ Переименование (Rename)
│   ├─ Выделение метода (Extract Method)
│   ├─ Выделение класса (Extract Class)
│   ├─ Инверсия условий (ранний return)
│   └─ Замена магических чисел константами
│
└─[хранение данных]──► ORM / EF CORE
    ├─[подход]──► Code First  "сначала модели, потом БД"
    ├─[компоненты]──► DbContext
    │               ──► DbSet<T>
    │               ──► Migrations / EnsureCreated
    ├─[запросы]──► LINQ
    │   ├─ Include  "жадная загрузка навигаций"
    │   ├─ GroupBy + Count
    │   ├─ GroupBy + Average
    │   └─ OrderBy / ThenBy
    └─[СУБД]──► SQLite
```

## Связи между блоками

| Понятие A | Отношение | Понятие B |
|---|---|---|
| DIP (SOLID) | является основой для | Внедрение зависимостей |
| DI-контейнер | автоматизирует | Точку сборки |
| Стратегия | реализует | OCP (SOLID) |
| Стратегия | требует | Dependency Inversion (DIP) |
| Тестируемость | достигается через | DI + абстракции (IClock, ILogger) |
| TDD | применяет | xUnit + Moq |
| Рефакторинг | улучшает соответствие | SRP, DRY, KISS |
| EF Core | использует | Code First + LINQ |
| CRUD в GUI | реализуется поверх | EF Core + WinForms |
